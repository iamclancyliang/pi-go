# Pi 功能清单

这份清单回答一个问题：**Pi 这个产品到底有哪些功能。**

用平常话写，按用户能感知的领域分类。工程记号（功能 ID、文件行号、类型名）不在这里，它们在
`pi-feature-inventory.md`（英文，给工程和校验用）。

**每项功能具体怎么用**，见 `pi-使用说明.md`——按命令行、交互界面、会话、工具、扩展、模型、RPC、SDK
分节，含前置条件、最小用法、限制与降级。

**基准**：`earendil-works/pi` 的 `086c32e7`。所有内容都是从这个固定版本的源码里读出来的，不是凭印象写的。

## 怎么读这份清单

每一项后面的标记表示**我们的确认程度**，不是功能的好坏：

| 标记 | 含义 |
| --- | --- |
| ✅ | **已确认**：从源码里逐条读出，成员可以机器重新生成并校验 |
| 🟡 | **部分确认**：知道有这个东西，但还没逐项查完 |
| ⚠️ | **有坑**：移植时容易做错，下面会说清楚错在哪 |
| ❌ | **查不到**：这个基准版本里没有可查的证据（不等于功能不存在） |

**看到 🟡 请当作「还没查完」，不要当作「查完了只有这些」。** 这份清单目前**尚未通过独立校验**，
校验完成后标记会再更新一次。

## 怎么自己验证

不用相信我们的结论，可以自己跑：

```bash
# 重新生成功能条目，并校验成员是否与源码一致
cd pi-go
python3 tools/gen-feature-ids.py --pi-repo /path/to/pi \
        --check-providers tools/expected-providers.txt
```

- **退出码 0** 且打印 `provider set matches` = 生成结果与源码一致；
- **非 0** = 有问题，屏幕上会写明是哪一项、缺什么或多什么。**它宁可报错也不会猜**。

工具只读固定版本 `086c32e7`，不看你本地 pi 仓库的当前状态，所以结果不会因为谁拉了新代码而变。

## 一、命令行

**四种运行形态** ✅
- **交互式**：完整终端界面
- **打印**：跑一次、输出结果就退出
- **JSON**：把过程以 JSON 逐行输出，给程序消费
- **RPC**：常驻，接命令、发事件

⚠️ **形态是运行时按终端状态决定的，不只看参数。** `--mode` 只接受 `text`/`json`/`rpc` 三个值；
`text` 的实际结果取决于**标准输入和标准输出是不是终端**——在终端里得到交互式，一旦被重定向（比如接管道）
就自动变成打印模式。**交互式无法用参数直接指定**，它只是「两端都是终端且没加 `--print`」时的默认值。

**40 个命令行参数** ✅ —— 覆盖：选模型与厂商、指定或追加系统提示词、会话（继续/恢复/新建/指定目录/
分叉）、工具开关与白黑名单、思考等级、扩展与技能与提示词模板与主题的加载或禁用、打印与导出、
主题、审批开关、离线模式等。

**22 个斜杠命令** ✅ —— `settings` `model` `scoped-models` `export` `import` `share` `copy` `name`
`session` `changelog` `hotkeys` `fork` `clone` `tree` `trust` `login` `logout` `new` `compact`
`resume` `reload` `quit`

## 二、会话

**会话是一棵树，不是一条线** ✅ —— 可以从任意历史位置分叉（`fork`）、原地复制（`clone`）、在分支间
导航（`tree`）。

**五种「换会话」操作**：新建、恢复、分叉、克隆、导入 ✅

⚠️ **换会话不是「改个指针」，而是一整套拆卸重建。** Pi 会：先问扩展要不要取消 → 对旧的扩展实例发关闭
通知 → **把扩展全部卸载重装** → 再发启动通知。**扩展可以否决整个操作**，这也是为什么这几个操作会返回
「成功了，但什么都没做」。移植时如果只换状态、让扩展继续活着，扩展会带着过期数据继续跑，而且**不报错**。

**上下文压缩**（会话太长时自动或手动 `compact`）✅
- 触发条件：上下文超过「模型窗口减去预留额度」（预留默认 16384，可配置）
- 保留最近约 20000 token 的原文，更早的内容换成摘要
- ⚠️ **压缩不删任何历史**。它只是改变「发给模型的那份投影」，原始记录仍在会话里。移植时用「删消息」
  实现压缩，会**隐形地**丢掉历史——因为模型看到的下一次请求长得一模一样。
- ⚠️ **绝不能在「工具结果」处切断**：工具调用和它的结果必须留在一起。只按 token 预算切，早晚会切开。
- ⚠️ **摘要本身要花钱**，并计入会话总量。别把压缩当成零成本操作。

**分支摘要** ✅ —— 离开一个分支时，Pi 会把「你正在放弃的那条线」摘要后注入你要去的分支。
⚠️ **文件记录是累积的**：读过/改过哪些文件，会跨多次压缩和嵌套摘要不断累加。只按当前窗口统计，
**第一次看起来完全正确，第二次就丢历史**。

**导出与分享** ✅ —— 导出 HTML 或 JSONL、导入 JSONL、分享为私密 GitHub gist、复制最后一条回复。

## 三、工具

**7 个内置工具**（模型可调用）✅ —— `bash` `edit` `find` `grep` `ls` `read` `write`

另有一套**独立的 4 个工具**用于底层 harness（`bash` `edit` `read` `write`）✅ ——
⚠️ 这是**两套不同的工具集**，不是一套，harness 那套没有 `find`/`grep`/`ls`。

**并发规则** ✅ —— 一批调用默认并行；**只要其中有一个工具声明「不能并发」，整批都改成串行**。
⚠️ 顺序是可观察的契约：并行时「先全部开始、结束按完成顺序、结果按原始顺序」；串行时「一个走完再下一个」。

⚠️ **`edit` 的每处修改都对照原始文件匹配，且禁止重叠**——不是依次作用在改动后的文件上。

✅ **工具会影响系统提示词**：每个工具都往提示词里贡献一段说明，**启用哪些工具就改变了模型看到的输入**。

## 四、扩展

Pi 的扩展能力比「插件」更深——很多地方是**可替换的接缝**，不只是通知。

**能观察的**：会话生命周期、模型切换、思考等级变化、每条消息与每次工具执行、压缩与分支摘要、
自动重试、扩展报错 ✅

**能拦截或改写的** ✅
- ⚠️ **工具参数可以被就地改写，且不会重新校验**。（pi-go 目前只支持「放行/拒绝」，**不支持改写**——这是
  一处已知能力缺口。）
- **可以否决**：换会话、分叉、压缩、树导航
- ⚠️ **bash 后端可以整体替换**——官方例子是**把命令送到另一台机器上用 SSH 执行**。也就是说 shell 不是
  内置死的，而是一个接缝。
- ⚠️ **用户输入会经过五步流水线，扩展钩子不在第一位**：先匹配扩展命令（命中则钩子**根本不触发**）→
  钩子 → 技能展开 → 模板展开 → 交给模型。**钩子看到的是原始文本**，技能和模板都还没展开。
- **项目信任**：第一个给出「信任/不信任」的扩展**说了算**，并压制内置提示。项目本地扩展在信任确定前
  **不会被加载**。

**能提供内容的** ✅ —— 注册新工具、注册斜杠命令、贡献技能/提示词/主题的搜索路径、自定义渲染、
改写 Markdown、往会话里追加自定义条目。

**85 个官方扩展示例** 🟡 —— 覆盖 Git 检查点、权限门、SSH、状态栏、通知、子代理编排、
甚至在终端里跑 WASM 游戏。**尚未逐个对应到功能条目**，所以标为部分确认。

## 五、模型与厂商

**40 个内置文本厂商** ✅ + **1 个图像厂商** + **1 个测试用假厂商**
（涵盖 Anthropic、OpenAI、Google、Bedrock、Azure、各类网关与国内厂商等）

**认证** 🟡 —— API key 之外还有多种 OAuth 流程（设备码、PKCE 等）。流程细节未逐条查完。

❌ **「Pi 支持多少个模型」在这个基准版本里查不到。** 模型清单是**构建时生成**的，没有提交进仓库。
仓库里只有生成器。所以任何「支持 N 个模型」的说法都需要另找证据源，不能靠数文件。
（图像模型是提交进去的：45 个。）

**思考等级** ✅ —— 7 档（关闭 / 最小 / 低 / 中 / 高 / 超高 / 最大），可按等级配置 token 预算。

⚠️ **两层重试**：厂商层重试（同一次请求内）和会话层自动重试（**重新发起整个请求**）。
两者对扩展可见性不同——会话层重试会让相关钩子**再触发一遍**。

## 六、程序接口

⚠️ **有两套协议，不是一套。**

**1. 多会话线协议**（二进制 CBOR）✅ —— 9 个命令：列表、创建、附加、分离、提问、纠偏、中止、
设模型、设思考等级。带版本号、错误码、会话阶段。

**2. RPC 模式**（JSON）✅ —— **32 个命令**、**24 个事件**、**9 种界面请求**。
- 命令覆盖：提问/纠偏/后续消息/中止、状态与消息查询、模型与思考等级的设置与轮换、队列模式、
  压缩、重试、bash、会话统计与导出与切换与分叉与克隆与树、命令列表。
- ⚠️ **提问/纠偏/后续消息的返回只是「收到」，不是「做完了」**——真正结果通过后续事件到达。
- ⚠️ 有些命令返回「成功但已取消」，意思是**用户或扩展中止了操作**，不是失败。
- ⚠️ **有 3 个事件确实会发出但官方文档没写**，我们是从源码里找到的。

**SDK（把 Pi 当库嵌入）** 🟡 —— 13 个官方示例覆盖模型、提示词、技能、工具、扩展、上下文文件、
提示词模板、认证、设置、会话、完全控制。接口细节未逐条查完。
